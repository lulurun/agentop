# UI layout

The app's layout is fixed. This page names each part of it, says what goes where, and gives the keys that reach each part. Why the UI is shaped this way is in [0_00_design.md section 10](0_00_design.md#10-ui). Plugins fill this layout; they don't add parts to it (see [Rules for plugins](#rules-for-plugins)).

## The parts

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [◧]  ● devhost ▾   Sessions  Dialogues  Memory                     [⚙]  [◨]  │  header
├──────────────┬───────────────────────────────────────────────┬───────────────┤
│ ▾ Section    │ [tab][tab][tab]       │ [tab][tab]            │ ▾ Section     │
│   …          │                       │                       │   …           │
│ ▾ Section    │   buffer              │   buffer              │ ▸ Section     │
│   …          │                       │                       │               │
│              │   left area           │   right area          │               │
│ left panel   │            middle panel                       │ right panel   │
└──────────────┴───────────────────────────────────────────────┴───────────────┘
                                   body
```

| Name | What it is | In the code |
|------|------------|-------------|
| **Header** | The bar across the top | `App.tsx`, `.header` |
| **Left panel toggle** | Shows or hides the left panel | `App.tsx` |
| **Connection manager** | Which service the app is connected to: switch, add, Status of each | `ServiceSwitcher.tsx` |
| **Feature nav** | One button per feature, the current one highlighted | `FeatureNav.tsx` |
| **Feature** | A top-level part of the app: Sessions (core, the `default` project), Projects, Dialogues and Memory (plugins), more from plugins. Each has its own left panel, right panel, background and tabs | `features.ts` |
| **Settings button** | Opens Settings, the app's own settings | `App.tsx` |
| **Right panel toggle** | Shows or hides the right panel | `App.tsx` |
| **Body** | Everything below the header: left panel, middle panel, right panel | |
| **Left panel**, **right panel** | The feature's side panels. Their content is sections only | `.sidebar`, `.details` |
| **Section** | A titled part of a panel. Clicking the title folds it; a panel with one section still has its title | `Section.tsx` |
| **Middle panel** | Between the panels. Shows the background, or one or two areas | `MainArea.tsx`, `.main` |
| **Background** | What the middle panel shows with no areas: the feature's placard | a feature's `background` |
| **Left area**, **right area** | The middle panel split in two. Either can be there alone, and then fills the middle panel | `Workbench.tsx`, `Layout.left`, `Layout.right` |
| **Active area** | The area last used. Tab keys act on it, and the right panel follows its tab | `Layout.focused` |
| **Tab** | One entry in an area's tab bar; the area shows one tab's buffer at a time. A pinned tab can't be closed | `Tab` in `tabs.ts` |
| **Buffer** | What a tab shows: a session's terminal, a file, a past session, a service's Status, a plugin's view | `TabContent` in `tabs.ts` |
| **Dialogs, menus, toast** | Drawn over the layout by the core: Settings, the connection manager's menu, a tab's menu, an error | |

Both side panels are resizable and collapsible, remembered per client. Below 900px they become overlays and start collapsed; below 600px the feature nav becomes a drop-down, so the header still fits on a phone.

## The features

| Feature | Left panel | Middle panel | Right panel |
|---------|------------|--------------|-------------|
| Sessions (core) | New session; Active sessions; History | The start buffer in the left area; session tabs, past sessions, files, Status | The active tab's session: details, usage, files |
| Projects (`projects`) | Projects (name field and Create, the list); then the chosen project's Active sessions and History | As Sessions | As Sessions |
| Dialogues (`dialogue`) | Create new dialogue; In progress; Finished | Agent A in the left area, agent B in the right, view only; artifacts open in tabs | The dialogue: status, stats, artifacts, Stop and Remove |
| Memory (`memory`) | None | The Search tab, pinned first in the left area: recent sessions, or results under All, Sessions and Mentions. A conversation per tab in the right area, opened at the mention | The conversation's summary and session |

A plugin's feature shows only while the plugin is enabled on that service; switching to a service without the current feature falls back to Sessions. Each feature's own doc says more: [0_13_projects.md](0_13_projects.md#72-projects-plugin-projects), [0_12_02_dialogue.md](0_12_02_dialogue.md#8-in-the-app), [0_12_03_memory.md](0_12_03_memory.md#6-the-memory-feature).

### Sessions

- **The start buffer** opens from New session in the left area: a session starts from its first prompt. The prompt box, and below it the sessions started from it, newest first. Sending clears the box; the row shows the tool, model and folder agentop chose, and the first prompt when it differs from what was typed, for 3 seconds (Change, Launch now, Cancel), or asks for the folder, then the session opens in a tab beside the buffer. Its settings (the probe's tool and model, the tool order, idle hours) are behind the gear in the buffer. How the choice is made is in [0_04_start.md](0_04_start.md).
- **Active sessions** lists the `default` project's sessions agentop started, newest first, with a keyword filter (which also filters History) and the count against the limit (`3/20`). Agents started outside agentop aren't shown.
- **History** lists past sessions ([design 4.5](0_00_design.md#45-history)), with a keyword filter and a CLI filter, newest first by last use. A past session opens as a tab showing its conversation, with **Resume** and **Delete** (asks first; deletes the transcript from its tool, and agentop's records of it) in the buffer's bar; the right panel shows its details, what its transcript holds, and its files.
- Clicking a section's title folds it; which are folded is remembered in this browser.

### The middle panel

What a session's buffer shows depends on its state:

| State | Shows |
|-------|-------|
| `starting` | Spinner, session name, and current step text |
| `running` | Terminal, focused |
| `exited` | Terminal with a banner: Resume, Close session |
| `failed` | The error, and the terminal if tmux exists |
| Reconnecting | Terminal dimmed, "Reconnecting…" |
| Service unreachable | The connection problem instead of tabs, with Retry, and in the desktop app for this computer's service, Start. Forget for a service other than this app's own |

The app asks its questions in the page (Stop session, Delete for good, and Close a project in a modal), never with `window.confirm`, `alert` or `prompt`: where a webview shows no such dialog, `confirm` answers no without a word, which is why the Projects trash button did nothing.

The web app asks before the page is left while a terminal is open (`beforeunload`), since Ctrl+W closes a browser tab rather than deleting a word.

## Tabs

- Each connection keeps one tab layout per feature. Switching features and back keeps the tabs, the split, and what was selected.
- A feature that opens with no tabs shows its background, which offers its New action. A default tab is **pinned**: it can be moved but not closed. Memory's Search tab is pinned first in the left area (a plugin's feature names its pinned view as `home`).
- Sessions' tabs stay mounted, hidden, while another feature shows, so terminals keep their connection and scrollback.
- Each area also keeps the last 3 sessions it showed, hidden (`KEEP_SESSIONS` in `Workbench.tsx`), so going back to one shows the same terminal at once instead of attaching again. A kept session goes when the tab that showed it closes, or when the session does. Each kept terminal holds a WebGL context and a socket, and a browser allows about 16 contexts.
- The core owns the `session`, `status` and `past` kinds; `file` is drawn by the `file-viewer` plugin; a plugin adds views of its own through its feature. When a plugin is turned off, its tabs close with its feature.

## Where tabs open

- An action in the **left panel** opens its tab in the **left area**; an action in the **right panel** opens it in the **right area**.
- An action in the **header** (Status in the connection manager) opens in the left area.
- An action inside a **buffer** (a link in a Markdown file) opens in that buffer's area.
- If the target area isn't there, it is made, and the middle panel shows it beside the other area if there is one.
- A session's tab opens in Sessions when it is in the `default` project, and in the feature shown when it is in another project ([0_13_projects.md](0_13_projects.md)); each feature has its own selected session, which its right panel shows.
- A tab already open in either area is shown where it is instead of opening twice.
- By default a tab takes the place of the target area's tab of the same kind (a session replaces the session shown); Ctrl or Cmd-click or the middle button opens a new tab.
- When an area's last tab closes, the area goes; when both have gone, the background shows.
- A tab can be moved to the other area from its menu, and a session or file shown in the other area too with the split button.

Two exceptions: picking a dialogue in Dialogues' left panel shows agent A in the left area and agent B in the right one; and a session or mention in Memory's Search tab opens in the right area, beside the search.

## Header

From the left: left panel toggle, connection manager, the feature nav, settings button, right panel toggle. Nothing else goes in the header but the update notices ([design 7.4](0_00_design.md#74-releases-and-the-update-indicator)): a feature's New button (New dialogue) is the only thing in the Create new … section at the top of its left panel (Projects has none: its name field is at the top of its Projects section; Sessions has none: it starts from the start buffer). The left and right toggles show only in features that have that panel.

### Connection manager

A menu of the saved services, then Connect to a service:

```
┌──────────────────────────────────┐
│ ● build-box                Status│
│ ● gpu-1  Not encrypted     Status│
│ ○ office-mini  Unreachable Status│
│ ──────────────────────────────── │
│       Connect to a service       │
└──────────────────────────────────┘
```

- Selecting a row switches at once ([design 3.2](0_00_design.md#32-connecting-to-services)). Rows show live reachability from `/health`, polled every 15s only while the menu is open.
- **Connect to a service**: URL (or a pasted `connect-info` string) and an optional name. Test runs the connection checks first. The form warns about unencrypted URLs and likely browser blocks.
- **Status**, on each row, opens a Status tab in the left area, switching to that service first.

### Settings and Status

- **Settings** (the gear) is the app's own, the same for every service: theme, terminal font size, and terminal drawing (`auto`, WebGL, DOM).
- **Status** belongs to a service, and is a tab: a name field (an alias kept only by this client), address, version and commit, uptime, tmux version, encryption, Stop, Restart and Update (enabled by what the service's manager can do, with an update's progress step by step), the signed-in clients, Forget (removes the service and its token from this client; never for the service that served the page), and the service's **Plugins**, each with its switch, state, any error, and its own settings section.

## Keys

All layout keys are Ctrl+Shift with a physical key (`event.code`, so they stay in place on any keyboard layout). The core takes them before the terminal or anything else in the page.

| Key | Does |
|-----|------|
| Ctrl+Shift+1 | Left panel toggle |
| Ctrl+Shift+2 | Connection manager: opens or closes its menu |
| Ctrl+Shift+3 to 8 | The first to sixth feature in the feature nav |
| Ctrl+Shift+9 | Settings |
| Ctrl+Shift+0 | Right panel toggle |
| Ctrl+Shift+Q | Focus the left panel, showing it if hidden |
| Ctrl+Shift+W | Focus the left area; nothing if there isn't one |
| Ctrl+Shift+E | Focus the right area; nothing if there isn't one |
| Ctrl+Shift+R | Focus the right panel, showing it if hidden |
| Ctrl+Shift+A, S, D, F, G, H, J, K | The first to eighth tab of the active area |
| Ctrl+Shift+M | Toggle the input bar |
| Ctrl+Shift+L | Close the active area's tab (a session's tab only: the session keeps running) |

A feature after the sixth, a tab after the eighth, and a panel the feature doesn't have get no key.

Everything inside a section or a buffer belongs to whoever draws it, the core or a plugin, and may have keys of its own, as long as they aren't the keys above. The terminal's: Ctrl+Shift+C copies the selection, Ctrl+Shift+/ searches its scrollback.

Some of these are browser shortcuts too (Ctrl+Shift+Q and W quit or close a window), but the page takes them first: in Chrome, Q, W, E, R and J all reach the app (checked 2026-11-19). Other browsers are unchecked.

## Rules for plugins

- A plugin's feature gives a label, optional left and right panels, a background, the views its tabs show, and optionally one of them as its pinned `home` tab. Nothing else in the layout is a plugin's.
- A panel's content is `Section`s (from `components/Section.tsx`), each with a title, also when there is only one.
- A plugin adds to a core feature only through the slots in `plugins/types.ts`: a section in Sessions' right panel (`rightPanel`), a badge in a session row, a piece below a terminal, a section in Status.
- Tabs are opened with the core's `openTab(content, area)`, never by editing a layout, so the rules in [Where tabs open](#where-tabs-open) hold everywhere.
- No new kind of part (another bar, a floating panel, a third area) until the core has one. Ask for it in the core first.
